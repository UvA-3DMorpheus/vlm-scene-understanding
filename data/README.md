# Data

Local data root. On Snellius `VSU_DATA_ROOT` points to `/projects/prjs2306/morpheus/data`
(exported by `scripts/snellius/env.sh`); on a laptop it is this folder. Only `smoke/`,
`materials/` and `annotations/` are versioned; everything else is gitignored.

```
data/
  sim/                 simulated scenes, MuJoCo preview look (generated by us, see below)
  sim_realistic/       the same scenes rendered with the Blender realistic look (from Emil)
  physion_pp/          Physion++ fallback set (scripts/download_physion_pp.py)
  smoke/               tiny labelled image set for tests, with labels.csv (versioned)
  materials/           materials.json (verbatim copy of the simulation team's file) and
                       material_table.yaml (our ranged table with sources), versioned
  annotations/         hand boxes and synonym tables, versioned
```

## Simulated scenes: the real format

The scenes come from Emil Halliday's `3D-Simulations` repository
(github.com/UvA-3DMorpheus/3D-Simulations, `docs/data_format.md`, ground truth schema 2.0).
This is the agreed format; our proposal from the planning stage is withdrawn. Each scene is one
folder, exactly as the pipeline writes it, dropped under `sim/<scene_id>/` or
`sim_realistic/<scene_id>/`:

```
<scene_id>/
  ground_truth.json        one moving object, surface, contact (mu_kinetic, mu_static,
                           restitution), expected analytic motion, provenance, per frame
                           centre of mass position, velocity, quaternion, angular velocity
  cameras.json             intrinsics K and pose for front, left, right, high, low
  checks.json              the pipeline's automatic validation; we keep only scenes that pass
  trajectory_highrate.npz  every physics step
  <camera>/rgb.mp4         H.264 clip, 24 fps, 640x480 by default
  <camera>/depth.npz       uint16 millimetres along the viewing axis, 0 = no surface
  <camera>/seg.npz         geom id per pixel; the object's id is object.segmentation_geom_id
```

What matters for us:

- **One object per scene.** Comparative questions (Experiment 3) pair objects across scenes.
- **Four scenarios**: `free_fall_no_contact` and `projectile_no_contact` (a primitive ball,
  simulated in MuJoCo), `rolling_without_slipping` (a painted ball) and `sliding_with_friction`
  (a coloured block or one of five Google Scanned Objects on an oak board), the last two with
  closed form trajectories. We call them free_fall, projectile, rolling, sliding.
- **Materials**: only the scanned objects carry a `material_class` (ceramic, metal, plastic,
  cardboard, book_paper_cover). Balls and the block have none. Restitution is null everywhere,
  since nothing bounces.
- **Five cameras** per scene. `front` is the Morpheus style level side view; the others see
  motion toward or away from the camera.
- **Masks for free**: `seg.npz` compared with `segmentation_geom_id` gives the exact object mask,
  so no hand boxes are needed for these scenes.
- **Determinism**: the MuJoCo preview output is byte identical across runs on the same machine
  (verified on the Snellius login node, 2026-10-14). The realistic Blender look needs Blender on
  Emil's Mac and is not bit reproducible, so it is generated once by him and shared.

`src/vsu/data/dataset.py` is the only code that reads these files. It converts
`ground_truth.json` into our `GroundTruth` model (`src/vsu/schemas/scene.py`), decodes frames
into `VSU_CACHE_ROOT/frames/<scene_id>/<camera>/000000.png ...`, and cuts object crops from the
segmentation. If the format changes, that module changes and nothing else.

### Generating the preview set

`scripts/generate_sim.py` runs the four scenarios from a pinned checkout of 3D-Simulations
(`VSU_SIM_REPO`, on Snellius `/projects/prjs2306/morpheus/envs/3D-Simulations`, commit `05c0043`)
into `VSU_DATA_ROOT/sim/`, headless (`MUJOCO_GL=egl`). The provenance block of every scene
records the commit it was generated from, and `sim/MANIFEST.json` records the run.

Generated 2026-10-14 on the Snellius login node: ten scenes at 640x480, 24 fps
(`high_drop`, `projectile`, `rolling`, `rolling_hollow`, `sliding_block`, and `sliding_<object>`
for tray, organiser, board_game, book, cereal_box). Nine pass every pipeline check. `rolling`
fails one renderer precision check only (depth back-projection 6.6 mm against a 5 mm limit on
the `right` camera); its physics checks pass, so it is usable for everything except depth
based work. `discover_scenes(only_passing=True)` excludes it; pass `only_passing=False` to keep it.

### Asks to the simulation team (Emil)

1. Realistic Blender renders of the same scenes (same commit, same options) into
   `/projects/prjs2306/morpheus/data/sim_realistic/<scene_id>/`, since material recognition needs
   textures, not flat colours.
2. A bouncing scenario with a defined coefficient of restitution, so restitution can be
   evaluated against ground truth at all.
3. A `material_class` for the balls and the block, or a few ball variants with different
   materials (steel, rubber, wood), to enlarge the material labelled set beyond five objects.
4. Scenes with two objects of different materials, for within scene comparative questions.

## Materials

- `materials/materials.json`: verbatim copy of the simulation team's file. Its SHA-256 is
  recorded in each scene's `provenance.materials_json_sha256`, so a mismatch means the scene was
  made with another version. Do not edit it; replace it when they publish a new version.
- `materials/material_table.yaml`: our ranges per material with sources, for the material first
  estimator and the synonym mapping. Our values, our responsibility.

## Smoke set

Eighteen photos from Wikimedia Commons in `smoke/`, two per material for metal, ping pong
plastic, wood, foam, ceramic, cardboard, book and glass, one each for rubber and plastic. Resized to
at most 800 px. `labels.csv` has `file,material,object,notes` plus `source_url,author,license`;
`ATTRIBUTION.md` lists the credits (all CC0, public domain, CC BY or CC BY-SA). Loader:
`vsu.data.smoke.load_smoke_set`. It is a sanity check only: it shows the pipeline works on real
photos. The benchmark is the simulated scenes; reports keep the two apart and never mix them.

## Physion++

The Elasticity and Friction subsets, downloaded by `scripts/download_physion_pp.py` into
`physion_pp/`. Loader in `src/vsu/data/physion_pp.py`. Not yet implemented.
